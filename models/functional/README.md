# Исполняемый Simulink-прототип — 7 Model Reference

Это **отдельная** демонстрационная модель, которую можно запускать независимо от предыдущей архитектурной `UAV_Team_Model.slx` и MATLAB-симуляции `run_project`.

## Как собрать в MATLAB Online

Переключитесь на ветку `feature/executable-simulink-architecture-20261123`, затем из корня проекта:

```matlab
build_functional_simulink_model
run_functional_demo
run('tests/run_functional_simulink_tests.m')
```

Скрипт создаёт в `models/functional/generated/` девять файлов: **7 .slx участников**, **1 .slx Dynamics**, **1 верхнеуровневая .slx**. В отличие от прежней обзорной схемы, внутри этих 8 компонентных моделей есть работающие MATLAB Function-блоки.

Отдельно `models/functional/dynamics_step.m` — общая Dynamics.

## Что модель действительно выполняет

- Дискретный двумерный полёт (XY): движение, ограничение скорости, расход батареи.
- Оценку положения и скорости с фильтрацией.
- Выбор следующей контрольной точки **из заранее построенного** MATLAB-маршрута.
- Вычисление расстояния до ближайшего неподвижного круглого препятствия.
- Команды ускорения, реактивное ограничение при угрозе сближения.
- Формирование вектора телеметрии, запись `uavf_telemetry`, `uavf_state`, `uavf_target`.
- Все семь модулей находятся в отдельных, исполняемых Simulink Model Reference.

## Ограничения, которые нужно сказать преподавателю

- Это **2D прототип**, а основная MATLAB-миссия остаётся 3D, как в `run_project`.
- Маршрут строит исходная MATLAB-функция **до** запуска Simulink, блок №03 во время полёта только переключает waypoint.
- Навигация получает идеализированное состояние и сглаживает его; полноценные GPS, IMU и фильтр Калмана отсутствуют.
- Обнаружение использует виртуальные круговые препятствия; камеры, распознавания изображений и динамических объектов нет.
- Энергетика — процентная модель; тяга, ветровые возмущения, аэродинамика и вращательное движение не моделируются.
- Эвристическая реакция безопасности не гарантирует отсутствия столкновений во всех условиях.
- Эти .slx не предназначены для реального полёта или автономного управления физическим БПЛА.

## Исправление ошибки `Array element 3 is out-of-bounds`

Причина: в раннем генераторе у входов отдельной Model Reference не были явно заданы размеры. В том числе блок `UAVF_Detection_04/Obstacles` мог компилироваться как скаляр вместо матрицы 3×N.

После `git fetch` и обновления этой ветки вызови **один раз**:

```matlab
repair_functional_ports
set_param('UAVF_Team_Model','SimulationCommand','update')
run_functional_demo
run('tests/run_functional_simulink_tests.m')
```

Команда `repair_functional_ports` создаёт бинарные резервные копии восьми моделей в `models/functional/backups/`, обновляет только размеры входных портов и сохраняет модели. **Не удаляй папку generated**. Новые сборки, созданные исправленным генератором, сразу получают правильные размеры.

Предупреждение MathWorks `rpiutils.internal.getLinuxRoot` относится к отдельной регистрации Raspberry Pi toolchain, а не к причине ошибки `Obstacles`. Если после исправления размеров возникнет другая ошибка, сохрани её полный текст.

## Исправление алгебраической петли (`Waypoint Planning` / `Dynamics`)

В Simulink Model Reference возможно трактовать часть выходов как `direct feedthrough`. При наличии внутреннего `persistent waypointIndex` это вызвало ошибку алгебраической петли, несмотря на задержку внутри Dynamics. Исправление добавляет **явный Unit Delay на уровне UAVF_Team_Model** между состоянием Dynamics и входами модулей Navigation/Energy. Это означает дополнительный шаг задержки оценки для контроллера (0,1 с), который необходимо учитывать в интерпретации результатов.

Для существующей локально собранной схемы после получения исправленного кода:

```matlab
repair_functional_feedback
set_param('UAVF_Team_Model','SimulationCommand','update')
run_functional_demo
run('tests/run_functional_simulink_tests.m')
```

`repair_functional_feedback` **не удаляет** сгенерированные модели и делает копию верхнеуровневого `.slx` в `models/functional/backups/` перед изменением. В новых сборках генератор сразу создаёт этот Unit Delay.

## Воспроизводимость и безопасность файлов

Генератор **не перезаписывает существующие .slx**. Если нужно обновить исходники модели и пересоздать файлы, сначала сохраните их резервную копию или переименуйте папку `models/functional/generated/` вручную. Старые `models/generated/UAV_*.slx` остаются без изменений.

В Git включены исходники и сценарий генерации, **файлы .slx создаются локально при выполнении MATLAB**. Перед защитой зафиксируйте проверенные `.slx` в отдельном командном PR и приложите вывод тестов.
