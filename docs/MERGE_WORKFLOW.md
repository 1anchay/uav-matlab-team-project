# Схема совместной работы

1. `main` хранит рабочую интегрированную версию.
2. У каждого участника есть постоянная персональная ветка `team/...`.
3. Участник подтягивает свежий `main`, делает свою часть и запускает тесты.
4. Изменения отправляются Pull Request'ом в `main`.
5. При конфликте интерфейсов сначала правится `docs/INTERFACES.md`, потом код.
6. После merge остальные участники подтягивают обновлённый `main` в свои ветки.

## Перед merge обязательно
- `run_project` запускается;
- `run('tests/run_tests.m')` проходит;
- основной сценарий достигает цели или причина нового статуса объяснена;
- нет случайных изменений чужих файлов;
- новый код прокомментирован достаточно, чтобы другой участник понял логику.
