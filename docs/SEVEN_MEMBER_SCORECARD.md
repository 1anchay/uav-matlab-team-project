# Семь самостоятельных результатов: измеримые KPI и тесты

Чтобы участие каждого было содержательным, инженерные критерии должны быть
связаны с отдельным исходным файлом и проверкой.

| ID | Модуль | Входные данные | Выходные данные | Главный проверяемый KPI | Где проверять |
|---|---|---|---|---|---|
| 01 | Навигация | состояние, GPS valid | [x,y,vx,vy] | конечность/восстановление оценки после dropout; RMSE | `v3_navigation.m`, `run_v3_algorithm_tests` |
| 02 | Управление | nav, target | acceleration | норма ускорения ≤3 м/с², ограничение скорости | `v3_control.m`, V3-C |
| 03 | Планирование | nav, observations, goal | waypoint, план событий | 1 событие replan на первый новый круг; существующая карта хранится | `v3_replanner.m`, V3-D |
| 04 | Обнаружение | nav, 2 круга | список видимых + nearest | дальность обнаружения 35 м, фиксированные размеры | `v3_detection.m`, V3-01 |
| 05 | Наземная станция | nav, battery, threat, GPS, plan | 9-канальная телеметрия | значения конечны, размер 9×1 | `v3_ground.m`, V3-06 |
| 06 | Безопасность | command, nav, nearest, energy | safe command, code | ограничение ≤3 м/с², действие при угрозе и low battery | `v3_safety.m`, V3-04 |
| 07 | Энергосистема | state, command | drain, battery, flag | корректный положительный расход, заряд не увеличивается | `v3_energy.m`, V3-05/C |

**Подтверждённые результаты:** V3 unit 6/6 PASS, V3 Simulink 4/4 PASS,
один replan, 20 шагов GPS outage, 11.75 м до круга, максимум скорости
7.01 м/с. Отдельные показатели Advanced V2: RMSE 0.171 м, доставка
96.1%, зазор 9.39 м и 1 online replan. Эти показатели нельзя смешивать
или приписывать другой версии.

## Какой материал подготовить каждому

Каждый участник должен принести не только код, но и:

1. Схему входов/выходов собственного модуля с единицами измерения.
2. Случай штатной работы и отдельно случай ошибки/ограничения.
3. Скриншот собственного Model Reference или MATLAB Function.
4. Объяснение реализации, параметров, возможных отказов.
5. Минимум один тест с результатом PASS **после фактического запуска**.
6. Описание того, что в модели упрощено относительно физического БПЛА.

Отдельные личные директории `team/NN_Фамилия_Имя/` используются для
изменений каждого участника. Согласование общих интерфейсов идёт через PR;
кто именно написал конкретные изменения, должен отражаться в Git-истории
и командном отчёте, без фиктивного авторства.
