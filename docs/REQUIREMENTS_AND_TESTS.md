# Требования, интерфейсы и проверки учебного проекта

Таблица связывает спецификацию, MATLAB-модули и тесты: первая ступень прослеживаемости требований для Model-Based Design. Основано на рекомендациях MathWorks из `model-oriented.pdf` (особенно страницы 9–14).

## Ограничения принятия результата

**Проверки кода ещё нужно выполнить в настоящем MATLAB/Simulink.** Команды:

```matlab
run_project
run('tests/run_tests.m')
build_component_models
build_simulink_model
run('tests/run_simulink_smoke_tests.m')
```

Последние три требуют Simulink; `run_project` и `tests/run_tests.m` используют только базовый MATLAB.

## Уточнения к модели

- Препятствия представлены кругами в плоскости XY; независимой высоты у препятствий нет.
- Фильтр навигации, прогноз времени до столкновения и алгоритм безопасности — учебные приближения; не доказана безопасность реального дрона.
- Simulink **Model Reference** сейчас архитектурные заглушки. Перенос MATLAB-алгоритмов в исполняемые .slx — отдельный этап с верификацией.
- Умение защитить проект означает продемонстрировать *требование → модель → тест → результат*, а не просто показать красивую блок-схему.
- В дальнейшем нужны сценарии с динамическими препятствиями, потерей GPS, низким зарядом и вариацией настроек; результаты следует сохранить и задокументировать.
