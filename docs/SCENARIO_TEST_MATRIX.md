# Системные испытания UAV — сценарии, критерии и ограничения

## Зачем эти испытания

Один полёт `GOAL_REACHED` показывает интеграцию, но не устойчивость к отказам.
Для команды из 7 разработчиков нужны независимые проверки интерфейсов и отдельные
сценарии, где системы реально имеют значение. Статус выполнения проверок приведён ниже. Первоначальные критерии оставлены без изменений.

## MATLAB-кампания (основная модель XYZ)

`run_verification_campaign` запускает:

| Сценарий | Изменение | Критерий |
|---|---|---|
| Nominal mission | Три известных препятствия | `GOAL_REACHED` |
| Clear map | Убраны все препятствия | `GOAL_REACHED` |
| Radio blackout | Вероятность потери пакетов = 100% | `GOAL_REACHED`, 0 доставленных пакетов |
| Critical battery | Батарея на старте ниже 5% | `LOW_BATTERY`, немедленная остановка |
| Monte Carlo x10 | Разные seed для шума и потерь связи | Измерить успех, запас до препятствий и ошибку |

Дополнительно `tests/run_verification_campaign_tests.m` создаёт четыре
контрольные ситуации для Simulink-модуля №06: препятствие прямо по курсу,
критический заряд, невалидная навигация, нормальный полёт.

## Simulink challenge (функциональный 2D-прототип)

`run_hazard_experiment` использует `Simulink.SimulationInput` и
`setBlockParameter`: **не меняя .slx**, переопределяет матрицу известных
датчику препятствий, поставив препятствие на ранее измеренную штатную траекторию.
Маршрут в блоке 03 остаётся прежним: это проверка реакции на
**неизвестное планировщику неподвижное препятствие**, а не движущийся объект.

Требования: `safetyCode==1` хотя бы один раз, конечные числовые значения,
физический круг препятствия не пересекается фактической траекторией.
Тест: `run('tests/run_hazard_experiment_tests.m')`.

**Важное отличие:** обнаружение и реакция ещё не означают успешного обхода.
Тест должен завершаться ошибкой при столкновении; не скрывайте отрицательный
результат и не утверждайте, что система умеет предотвращать любые столкновения.

## Фактически наблюдавшиеся результаты (MATLAB Online, 23.11.2026)

- `run_hazard_experiment`: новый неподвижный объект [21.66, 38.50] радиуса 3.0 м; реакция защиты — 50 дискретных шагов; минимальный физический зазор — 2.66 м; цель достигнута с ошибкой 0.00 м. Строка `Hazard challenge PASSED` получена.
- На графике Monte Carlo **10 успешных seed из 10**, положительные расстояния до препятствий. Это не оценка вероятности отказа с высокой достоверностью.
- Полный вывод детерминированной кампании теперь предоставлен: **4/4 системных сценария PASS**, **4/4 поведенческих испытания Safety PASS**, **10/10 Monte Carlo GOAL_REACHED**. При этом все терминальные режимы нового Mission Supervisor внутри Simulink пока отдельно не проверены.

## Команды

```matlab
% Базовая проверенная программа
run('tests/run_tests.m')
run('tests/run_functional_simulink_tests.m')

% Подтверждены: 4/4 системных, 4/4 Safety и 10/10 Monte Carlo;
% hazard challenge тоже пройден. При изменении кода выполнять повторно
run_verification_campaign
run('tests/run_verification_campaign_tests.m')
run_hazard_experiment
run('tests/run_hazard_experiment_tests.m')
```

Испытания учебной симуляции не подтверждают пригодность к полётам
физического БПЛА. MATLAB-версия XYZ и 2D Simulink остаются разными моделями.
