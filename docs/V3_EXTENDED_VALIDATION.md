# V3 — расширенные интеграционные испытания перед защитой

## Зачем нужен отдельный этап

Уже подтверждены V3 unit **6/6 PASS** и Simulink integration **V3-A–D 4/4
PASS** для базового учебного мира. Это ещё **не** подтверждает поведение
при двух физических препятствиях, коллизии и критическом заряде.

**Новое:** шесть сценариев с независимыми ожидаемыми кодами миссии.
Все запускаются через `Simulink.SimulationInput` и не перезаписывают
сгенерированные `.slx` файлы. `UAV3_Team_Model` по-прежнему содержит
7 персональных Model Reference и 2 общих.

## Сценарии и критерии

| Сценарий | Ожидаемый код | Что проверяем |
|---|---:|---|
| `baseline` | 1 GOAL_REACHED | Один обнаруженный круг, ≥1 replan, позитивный swept clearance |
| `two_unknown` | 1 GOAL_REACHED | Два физических круга, ≥2 открытия и перепланирования, нет столкновений |
| `collision_at_start` | 2 COLLISION | Старт внутри круга: детерминированный приоритет столкновения |
| `critical_battery` | 3 LOW_BATTERY | Старт с зарядом 4%, немедленное завершение |
| `invalid_state` | 4 INVALID_STATE | Инициализация NaN, честная диагностика некорректного состояния |
| `goal_at_start` | 1 GOAL_REACHED | Уже на цели при нулевой скорости |

Для терминальных стартовых случаев дополнительно требуется остановка за
не более 0.2 с. Для полётных кейсов измеряется **swept clearance**
(минимум по всему отрезку между соседними записями, а не только по точкам).

**Важное ограничение:** новый двухкруговой сценарий специально сложнее
проверенного V3. Его успех **не утверждается** до фактического запуска.

## Запуск в MATLAB Online

Сначала перейти на ветку
`feature/v3-fault-injection-defense-readiness-20261123`
(с сохранением любых локальных изменений), затем:

```matlab
% Быстрый MATLAB-only тест новых входных форматов и геометрии
run('tests/run_v3_scenario_contract_tests.m')

% Диагностика — показывает даже FAIL и не прерывает цикл
campaign = run_v3_acceptance_campaign(true);

% Записать фактические данные, в том числе неудачные случаи
export_v3_acceptance_report(campaign)

% Строгая приёмка (может завершиться ошибкой, если есть дефекты)
run('tests/run_v3_extended_integration_tests.m')
```

Скрипт `run_v3_acceptance_campaign` возвращает таблицу `rows` и
исходные `runs`. `acceptance.csv` и `RESULTS.md` сохраняются локально
в `results/v3/extended/` (исключено из Git).

Если **двухкруговая модель не достигнет цели или столкнётся**, это
помечается FAIL, а не автоматически исправляется результатом V2.
При ошибке компиляции или невозможности смоделировать NaN-инициализацию
скрипт запишет ERROR; потребуются дополнительные изменения в
отдельной экспериментальной ветке.

## Подготовка к защите

1. Показать **уже подтверждённые** результаты Advanced V2 и V3.
2. Показать результаты новой кампании только после выполнения.
3. Попросить каждого участника объяснить одну проверку своего модуля.
4. Сохранить оригинальные `.slx`, CSV и выбранные изображения (в Git —
   только согласованные командой файлы).
5. После согласования испытаний подготовить презентацию на 12–14 слайдов:
   постановка задачи, архитектура семи модулей, Model Reference, алгоритмы,
   планирование, безопасность, результаты V2/V3, robustness, ограничения,
   распределение работ и ответы на вопросы.
6. Презентацию **пока не создаём**: её оформим отдельно после итоговой
   проверки и согласования фактических результатов.

## Оговорки

Это **синтетическая учебная 2D-модель** с двумя фиксированными кругами;
в ней нет полноценной 3D аэродинамики, реальных сенсоров, динамических
препятствий и оборудования. Положительные результаты не доказывают
безопасность реального полёта.
