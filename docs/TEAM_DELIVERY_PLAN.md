# План серьёзного проекта: семь участников, семь доказуемых результатов

**Суть:** семь отдельных блоков Simulink ещё не гарантируют семь самостоятельных инженерных результатов. В университете вклад каждого участника нужно подтверждать контрактами, испытаниями, графиками и анализом ограничений.

## Что уже проверено

- MATLAB-миссия XYZ: 11/11 проверок, GOAL_REACHED (вывод пользователя в MATLAB Online).
- Simulink обзорная схема: прошёл smoke test (структурная проверка).
- Исполняемая XY-модель: проверена компиляция, 8 Model Reference, GOAL_REACHED [100,80], v_max=9.87 м/с, остаток 88.59%, без столкновений **в базовом сценарии**.
- В базовом сценарии **0** срабатываний безопасности: аварийный режим требует отдельного испытания.

## Этапы расширения (проверяемые)

**M1. Испытания и доказательства (новая ветка)**

- `run_verification_campaign.m` — штатная миссия, карта без препятствий, полный обрыв связи, критический заряд и 10 случайных seed.
- `tests/run_verification_campaign_tests.m` — инженерные критерии и unit tests failsafe.
- `run_hazard_experiment.m` — дополнительное препятствие вне предварительного маршрута через SimulationInput (исходные .slx не меняются).
- `plot_verification_dashboard.m` — шесть измеримых графиков, отдельный reliability sweep.
- `polish_functional_model.m` — цветовое разделение модулей в Simulink с резервной копией модели.
- Критерий: все штатные сценарии и отдельные проверки проходят в MATLAB Online; отрицательные результаты stress-тестов документируются, не скрываются.

**M2. Настоящее online route planning**

- Новая компонентная версия Route Planning с выбором безопасного обхода при обнаружении ранее неизвестной преграды.
- Отдельный state machine для MISSION / REPLAN / AVOID / RETURN / FAILSAFE.
- Новый закрытый набор сценариев (плотные препятствия, GPS outage, low battery).
- Критерий: несколько пересечений карты / изменённых условий без коллизий; вычислительное время измерено.

**M3. Физическая достоверность**

- Согласованная 3D-модель трансляции/вращения квадрокоптера, двигателей и ограничений;
- Имитаторы GPS, IMU, altimeter, sensor fusion;
- Энергетика с массой, тягой и нагрузкой;
- Сопоставление MATLAB vs Simulink по одному сценарию;
- Критерий: известные контрольные траектории и проверенные единицы измерений.

**M4. Защита и командная интеграция**

- Зафиксировать проверенные `.slx` в GitHub, скриншоты в `docs/results/`.
- Защитить `main` и ревью каждого участника.
- Подготовить 7 коротких объяснений «вход → алгоритм → выход → тест».
- Готовность только после 7 индивидуальных демонстраций и общего прогона.

## Почему нельзя просто нарисовать сложную схему

Графические блоки должны отражать вычисления и единицы измерения. Реалистичные подсистемы и отказоустойчивость — содержательная инженерная работа; больше блоков без тестов только усложнят защиту.
